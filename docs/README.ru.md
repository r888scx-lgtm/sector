# Сектор 0.3.6 — Windows x64

Автор: **by.mask21**. Экспериментальная программа для клонирования SSD. Исходный код закрыт.

## Запуск и язык

1. Скачайте из Releases архив `Sector-0.3.6-Windows-x64.zip` и распакуйте целиком. Обе DLL AlphaVSS должны оставаться рядом с EXE.
2. Нужны Windows x64, Windows PowerShell, .NET Framework и Microsoft Visual C++ 2019/2022 x64 runtime. Программа разрабатывалась для Windows 10/11 x64; другие конфигурации не проверены.
3. Для клонирования запустите `Sector.exe` от имени администратора. `Sector-Preview.exe` показывает демонстрационные диски и не записывает на физические устройства.
4. Вверху окна выберите **Русский**, **English** или **简体中文**. Перевод применяется сразу, выбор сохраняется в `%LOCALAPPDATA%\Sector\settings.json`. Во время операции смена языка отключена.

## Перенос Windows

1. Подключите SSD назначения: его физическая ёмкость должна быть не меньше источника, а логический сектор — того же размера, 512 или 4096 байт.
2. В «Управлении дисками» переведите в Offline **только назначение**. Работающую Windows оставьте Online. Если назначение защищено от записи, кнопка в его карточке позволяет снять программный флаг «только чтение». Клонирование от этого не начинается.
3. Слева выберите источник, справа — назначение. Нажмите «Проверить план». Можно предварительно выполнить «Проверить VSS без записи»: это проверяет снимки, но не само клонирование.
4. Нажмите «Клонировать SSD». После предварительных проверок введите серийный номер назначения, который показывает Windows, и отметьте согласие на перезапись. При подключении через USB номер может отличаться от наклейки SSD и даже состоять только из нулей.
5. Дождитесь окончания копирования, полной проверки и подготовки загрузчика. Остановка или ошибка оставляет неполную копию. Прежние данные назначения программа не восстанавливает.
6. После успешного завершения выключите компьютер и отключите исходный SSD перед первой проверкой загрузки с копии. Не включайте назначение Online во время копирования или проверки.

## Поддерживаемые режимы

- Работающая Windows на обычном GPT: Windows и EFI должны находиться на одном исходном диске. Данные NTFS-томов переносятся через общий набор VSS. Копия отражает момент снимка, без более поздних изменений. EFI и разметка проверяются отдельно.
- Динамический GPT: поддерживается один **простой** NTFS-том текущей Windows и EFI на том же SSD. На назначении создаются обычная GPT, MSR 16 МБ, EFI и привязка системного тома. Составные и зеркальные тома, дополнительные пользовательские тома и неизвестные GPT-разделы отклоняются.
- Два несистемных Offline-диска: полная посекторная копия с побайтовой проверкой. Размеры разделов сохраняются; свободное место большего назначения автоматически к разделам не добавляется.
- MBR для работающей Windows, BitLocker в live-режиме, RAID, виртуальные диски, меньшее назначение, разные размеры логических секторов и автоматическое расширение разделов не поддерживаются.

Все скопированные данные перечитываются. VSS-копии сравниваются с SHA-256 блоков, сохранёнными до записи назначения. Проверки идентификаторов и состояния дисков работают на всех языках.

## Статус и журналы

Версия 0.3.6 экспериментальная. Полная запись и проверка тома Windows подтверждены на одном испытанном компьютере. Другие конфигурации и варианты загрузки требуют проверки. Сохраните независимую резервную копию важных файлов.

Интерфейс, справка и сообщения программы переведены. Ошибки Windows и драйверов, а также стандартные кнопки Windows могут следовать языку ОС. Технические журналы сохраняют исходную диагностику в `%LOCALAPPDATA%\Sector\logs`. Перед отправкой проверьте журнал: он может содержать идентификаторы устройств и пути.
